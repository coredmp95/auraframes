<objective>
Make every write failure carry its true name at the API boundary: a `batch_update` response that
silently drops requested ids reports them explicitly to every caller, a junk row inside an
otherwise-good batch response is skipped instead of costing the whole chunk, and the suite's one
red test stops asserting an equality the server itself does not honour.

Purpose: `assetApi` is entirely untested today (`codebase/CONCERNS.md` line 175), `Aura.upload_image`
throws away the only per-item signal the endpoint gives, and `test_read_03_pagination` is the
default suite's single failure — 149 drained vs 171 reported. Each of these is a place where the
system currently cannot tell you what happened.

Output: a named `batch_update` result type carrying the unacknowledged set, tolerant inbound
parsing with strict outbound validation, a fail-loud `upload_image`, and a pagination test that
asserts the cursor loop's own correctness.
</objective>

| T-11-05 | Tampering | inbound `successes` parsing | low | accept | A drifted or hostile response can suppress acknowledgement for an item that really landed.
