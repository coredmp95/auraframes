<objective>
Build the pure, offline-testable core of the dry-run sync engine: a directory
scanner that recursively finds and content-hashes eligible image files, and a
pure `compute_plan()` diff function that classifies a frame's assets into
upload / delete / unchanged against the local hashes.

Purpose: This is the structural enforcement of dry-run safety — the engine can
only ever compute a plan; there is no execute/mutating path in this module (the
future `execute_plan()` lands in Phase 8). Isolating the logic as pure functions
(mirroring Phase 6's `resolve_frame`) makes the whole diff testable offline with
no network and no credentials.

Output: `auraframes/sync.py` (scanner + diff + result dataclasses) and its
offline unit-test suite `tests/test_sync_engine.py`.
</objective>

    - A .mp4, a .DS_Store, and a .txt in the tree are counted in skipped_non_image and NOT hashed (D-02, D-03).

    - An empty directory yields empty local_hashes and skipped_non_image == 0 (no error).

  <action>
    Create `auraframes/sync.py`. Add `from __future__ import annotations`, and imports:
    `from dataclasses import dataclass, field`, `from pathlib import Path`, and
    `from auraframes.aws.s3client import get_md5` (reuse the canonical base64-MD5
    function — do NOT reimplement hashlib/base64 logic; that reuse is the whole
    point of SYNC-02).

    Define `ELIGIBLE_EXTENSIONS = frozenset({'.jpg', '.jpeg', '.png', '.heic'})`
    per D-02 (Claude's-discretion note allows extending this set only if the test
    directory surfaces other image formats, but videos/non-images must stay
    excluded). Eligibility is decided purely by lowercased file suffix — do NOT
    decode the image (a .heic is hashed as raw bytes even if Pillow cannot read
    it; we only need the byte content hash).

    Define a `ScanResult` dataclass with fields:
    `local_hashes: dict[str, list[Path]]` (content-hash -> every local path with
    that hash) and `skipped_non_image: int`.

    Implement `scan_directory(root: Path) -> ScanResult`:
    - Recursively walk `root` (D-01) using `Path.rglob('*')`; consider only
      regular files (`p.is_file()`). Do NOT follow into symlinked directories
      that could create traversal loops (rglob does not follow directory
      symlinks by default — rely on that and skip anything that is not a real
      file). This is the path-traversal mitigation for T-07-01.
    - For each file: if its lowercased suffix is not in ELIGIBLE_EXTENSIONS,
      increment `skipped_non_image` and continue (D-03: reported, never a hard
      error/abort).
    - Otherwise read bytes with `p.read_bytes()`, compute `h = get_md5(bytes)`
      (SYNC-02), and append `p` to `local_hashes[h]` (dedup grouping — D-05:
      identical content collapses to one key even across folders).
    - Return `ScanResult(local_hashes, skipped_non_image)`.

    Sort/normalize nothing that would hide duplicates; the dict grouping IS the
    dedup. Keep the function pure of any network/mutating I/O — the only I/O is
    reading local file bytes the user explicitly pointed at.

    - A local hash matching one frame asset -> unchanged incremented, that asset NOT in to_upload or to_delete (D-04: matched by content hash, not filename).

    - A frame asset with md5_hash == None (e.g. a video) -> excluded from unchanged AND to_delete, counted in frame_no_hash. (Prevents proposing deletion of every video, per the Phase 6 finding that videos carry a null md5_hash.)

  </behavior>
  <action>
    In `auraframes/sync.py` add a `SyncPlan` dataclass with fields:
    `to_upload: list[Path]`, `to_delete: list` (frame Asset objects),
    `unchanged: int`, `skipped_non_image: int`, and `frame_no_hash: int`. Use
    `field(default_factory=list)` for the list fields.

    Implement `compute_plan(local_hashes: dict[str, list[Path]], frame_assets:
    list, skipped_non_image: int = 0) -> SyncPlan`. It MUST be a pure function —
    no I/O, no network, no mutation of its inputs — mirroring `resolve_frame`.
    Algorithm:
    - Build a mutable demand map from `local_hashes`: for each hash key, remaining
      demand = 1 (D-05: local duplicates already collapsed to one logical want by
      scan_directory, so each unique hash demands exactly one frame copy).
    - Partition frame_assets:
      * If `asset.md5_hash` is falsy (None or empty) -> increment
        `frame_no_hash`, skip entirely (neither unchanged nor delete). This is
        the video-safety exclusion; do not classify hashless frame assets.
      * Else if that hash still has remaining local demand > 0 -> decrement the
        demand, increment `unchanged` (D-04 content-hash match).
      * Else (hash absent locally, or its demand already satisfied by an earlier
        frame asset) -> append asset to `to_delete` (D-06: surplus frame copies
        beyond local demand are delete candidates — the deliberate multiset
        asymmetry; do NOT dedupe the frame side).
    - After walking frame_assets, any hash whose demand is still > 0 (i.e. locally
      present but with no surviving frame match) -> add one representative Path
      (e.g. the first path in `local_hashes[hash]`) to `to_upload`.
    - Return SyncPlan(to_upload, to_delete, unchanged, skipped_non_image,
      frame_no_hash).

    Note: there is deliberately no `execute_plan()` in this module — the dry-run
    guarantee is structural. Do NOT add any function that calls upload/delete/S3;

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| user → filesystem | User-supplied directory path is recursively walked and each eligible file's bytes are read for hashing (untrusted local input: symlink loops, unexpected file types, large trees). |
| network → app | Frame asset metadata (`md5_hash`, `id`, `taken_at`) arrives from the already-live-verified read path; consumed read-only in this plan. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-07-01 | Denial of Service / Tampering | scan_directory recursive walk | medium | mitigate | Use `Path.rglob` (does not follow directory symlinks), operate only on `is_file()` regular files, and skip (count) any non-eligible file instead of failing — bounds traversal to real files under the user's own directory. |
| T-07-02 | Information Disclosure | reading arbitrary local file bytes | low | accept | Files read are exactly those under the path the invoking user chose to scan; no bytes leave the process (only a hash is retained). No cross-user exposure. |
| T-07-03 | Elevation / Tampering (write path) | absence of any mutating primitive | high | mitigate | Dry-run is structurally enforced: this module contains compute_plan only, never an execute/upload/delete path. Verify gate greps sync.py for mutating call tokens and requires zero. All genuine write-path threats are owned by Phase 8, not this phase. |
| T-07-SC | Tampering | npm/pip/uv installs | low | accept | No new packages introduced — hashing uses stdlib `hashlib`/`base64` via the existing `get_md5`, scanning uses stdlib `pathlib`. No install task, so no package-legitimacy exposure. |
</threat_model>
