<objective>
Deliver the first runnable v2.0 CLI: a packaged `aura-cli` command, distinct from `main.py`, whose only subcommand is `status`. `status` reports config health (are `AURA_EMAIL`/`AURA_PASSWORD` set?), attempts login, reports which account authenticated, and lists that account's frames — driving only the already-live-verified read path (zero new API risk).

Purpose: Establish the CLI entrypoint, the argparse subcommand skeleton (extensible for `inspect`/`sync` in Phases 6-8), and the scriptable non-zero-exit-on-failure convention (D-08) that later commands inherit.
Output: `auraframes/cli.py` (new), an offline test suite for `status`, and a `[project.scripts]` packaging entry.
</objective>

    `build_parser() -> argparse.ArgumentParser`: create `argparse.ArgumentParser(prog="aura-cli")`, add subparsers with `dest="command"` and `required=True`, and register a `status` subparser (`help="Check config/auth health and list account frames"`).     `run_status(aura=None) -> int`: the status handler. Return an int exit code; do NOT call `sys.exit` inside it (main() converts the return to the process code). Order of operations (config check MUST run first — D-09 depends on this ordering):
      1. Config health check (D-07): compute `email_set = bool(os.getenv("AURA_EMAIL"))` and `password_set = bool(os.getenv("AURA_PASSWORD"))`. Print exactly `AURA_EMAIL: set` or `AURA_EMAIL: NOT SET`, and the same for `AURA_PASSWORD`. Never print the password value or any partial/redacted form of it — only the literal words set / NOT SET.
      2. If NOT (`email_set` and `password_set`): return 1 immediately (D-09) — do NOT build an `Aura`, do NOT attempt login, make no network call.
      3. Build the facade with the injection seam: `aura = aura or Aura()` (only reached once creds are present). This lets tests inject an offline `Aura`; production passes nothing and gets a live one.
      4. Attempt login inside `try/except Exception as e` (D-08 must cover bad credentials, network error, and API drift — a broad catch at the CLI boundary is correct here): call `aura.login()`. On exception, print `f"Login failed: {e}"` and return 1.
      5. On success, fetch `frames = aura.frame_api.get_frames()`. Print `f'Logged in as {os.getenv("AURA_EMAIL")}'` (echo the configured email — matches D-05; the facade does not retain the User). Print `f"{len(frames)} frames:"`, then one line per frame formatted as `  - {frame.name} (id: {frame.id})` — name + id only, no asset/owner/contributor fields (D-06). Concise print-per-line format, no table (D-05). Return 0.

    `main(argv=None) -> int`: call `load_dotenv()` (so the installed command picks up a local `.env` the same way `main.py` does — keep load_dotenv OUT of `run_status` so tests can drive the handler without touching the filesystem). Then `args = build_parser().parse_args(argv)`. If `args.command == "status"`, `return run_status()`. Add the module guard: `if __name__ == "__main__": sys.exit(main())`.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| shell env → CLI process | `AURA_EMAIL`/`AURA_PASSWORD` (secrets) enter the process via env vars / `.env`; the CLI must not echo the password back to stdout. |
| CLI process → Aura cloud API | `status` sends credentials over the network via the existing `Client`/`Aura` login path (already live-verified read path; no new endpoints). |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-05-01 | Information Disclosure | `run_status` config-health output | high | mitigate | Print only literal `set`/`NOT SET` for `AURA_PASSWORD`; never the value or a partial. Enforced by Task 2 test asserting the password literal is absent from stdout, and by acceptance criterion grepping cli.py for a password-print path. |
| T-05-02 | Information Disclosure | login-failure message (`f"Login failed: {e}"`) | medium | mitigate | The caught exception is the existing `AccountApi` `RuntimeError`/`httpx` error, whose messages are API/status text, not credentials (login payload is redacted at the `Client` layer, see PATTERNS `_REDACT_KEYS`). Do not interpolate the password into any message. |
| T-05-03 | Denial of Service | live login network call | low | accept | `status` makes a single synchronous login+list call on the already-verified read path; no loop, no user-supplied volume. Acceptable at CLI scope. |
| T-05-SC | Tampering | pip/uv package installs | low | accept | No new packages are added — `argparse` is stdlib and `python-dotenv` is already a runtime dependency. `uv pip install -e .` installs only the local editable project; no third-party package legitimacy audit is triggered. |
</threat_model>
