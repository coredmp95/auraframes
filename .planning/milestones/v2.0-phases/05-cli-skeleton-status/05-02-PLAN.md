<objective>
Close the single diagnosed UAT gap for Phase 5: `aura-cli status` leaks verbose loguru INFO/DEBUG output (full request/response bodies, headers, cookies) to stderr, interleaved with its intended concise stdout. Root cause (fully diagnosed in the debug session): `Aura._init_logger()` adds an INFO-level stderr sink on every `Aura()` construction but never removes loguru's auto-registered default stderr handler (its `logger.remove()` is commented out and frozen per D-04), so two stderr handlers fire on every HTTP call.

Because `auraframes/aura.py` is frozen (D-04), the fix lands in `auraframes/cli.py`: after the `Aura()` instance exists, neutralize loguru's stderr handlers by default (keeping the on-disk file sink), and add an opt-in `--debug` flag to the `status` subcommand that leaves loguru's sinks untouched. Extend the offline test suite to assert on stderr so the regression is caught in CI.

Purpose: Deliver the concise `status` output the user expects while making verbose logging an explicit opt-in, without violating the D-04 freeze on `aura.py`/`main.py`.
Output: An updated `auraframes/cli.py` (a `--debug` flag + a logging-configuration helper wired through `main()`/`run_status()`), and two new stderr-focused tests in `tests/test_cli_status.py`.
</objective>
