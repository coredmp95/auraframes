## Pattern Assignments

### `auraframes/models/meta.py` (model, transform) — **REWRITE**

**Current state (entire file, 16 lines):** subclasses the v2-removed `pydantic.main.ModelMetaclass`.

```python
# auraframes/models/meta.py:1-15 (CURRENT — hard import-time break on v2)
from typing import Optional
import pydantic

class AllOptional(pydantic.main.ModelMetaclass):
    def __new__(self, name, bases, namespaces, **kwargs):
        annotations = namespaces.get('__annotations__', {})
        for base in bases:
            annotations.update(base.__annotations__)
        for field in annotations:
            if not field.startswith('__'):
                annotations[field] = Optional[annotations[field]]
        namespaces['__annotations__'] = annotations
        return super().__new__(self, name, bases, namespaces, **kwargs)
```

**Replace with:** the `create_model(__base__=model, ...)` factory — **RESEARCH.md Pattern 2, lines 215–223** (verified preserves methods, name, `isinstance`, all-optional + `exclude_unset`). The old metaclass merged `base.__annotations__` manually (the fragile part); the factory iterates `model.model_fields`, which already has forward refs resolved.

**Acceptance anchor:** factory must avoid `pydantic.main.*` / `pydantic._internal.*` (D-06); `hasattr(pydantic.main, "ModelMetaclass")` is `False` on 2.13.4.

### `auraframes/models/asset.py` (model, validation) — **`@validator` → `@field_validator`**

**Current validator (in-scope per D-05 — runs at import/class-def time):**

```python
# auraframes/models/asset.py:5   (import)
from pydantic import BaseModel, validator
# auraframes/models/asset.py:113-122  (AssetPartialId)
class AssetPartialId(BaseModel):
    id: Optional[str] = None
    local_identifier: Optional[str] = None
    user_id: Optional[str] = None

    @validator('id')
    def check_id_or_local_id(cls, _id, values):
        if not values.get('local_identifier') and not _id:
            raise ValueError('Either id or local_identifier is required')
        return _id
```

**Replace with:** RESEARCH.md Pattern 3 (lines 234–246) — `@field_validator("id")` + `@classmethod` + `ValidationInfo` (`info.data` replaces `values`). **Faithful straight port** (preserve the latent field-ordering no-op bug per Open Q#2 / A2; the `model_validator(mode="after")` fix is Phase 2).

**`Asset` base-model Optional landmine:** ~30 `Optional[...]` fields with no default (lines 33, 34, 36, 37, 38, 40, 41, 48, 49, 51, 53, 54, 56–61, 64–78, 85, 86, 92–96, 98–100). Same Open Q#1 decision as `Frame`. Note `Asset` uses `from __future__ import annotations` (line 1) — string annotations; the factory's `model_fields` iteration handles these, but base-model `= None` edits are plain source edits.

**Do NOT touch** the `.dict(...)` call sites in `api/assetApi.py` / `api/frameApi.py` — deferred to Phase 2 (D-05, RESEARCH.md anti-pattern line 299).

### `auraframes/utils/io.py` (utility, file-I/O) — **REPLACE `pydantic_encoder`**

**Current state (entire file, 18 lines):**

```python
# auraframes/utils/io.py:5-6  (line 6 is the v2 hard break — pydantic.json module removed)
from pydantic import BaseModel
from pydantic.json import pydantic_encoder
# auraframes/utils/io.py:16-18
def write_model(model: Union[BaseModel, list[BaseModel]], path: str):
    with open(path, 'w') as out:
        json.dump(model, out, default=pydantic_encoder)
```

**Replace with:** RESEARCH.md Pattern 4 (lines 258–267) — a `_pydantic_default(obj)` callable returning `obj.model_dump(mode="json")`, passed as `default=`. This preserves the `Union[BaseModel, list[BaseModel]]` signature and the `json.dump(..., default=...)` shape (`json.dump` recurses the list, applies `default` per element). **Avoid** the one-liner `json.dumps(model.model_dump())` — it silently drops the list branch (RESEARCH.md anti-pattern line 298).

## Shared Patterns

### Sibling pydantic model conventions (apply to all `models/*` edits)
**Source:** `auraframes/models/activity.py`, `user.py`, `person.py`
- Plain `class X(BaseModel):` — **no inner `Config` class anywhere** in the model layer (confirmed across all 5 model files). So v1 `class Config` migration is a non-issue this phase.
- Field names match API JSON keys directly; **no aliases** → RESEARCH.md's simple factory form suffices (alias branch unneeded, line 227).
- Correctly-defaulted examples to mirror when adding `= None`: `activity.py:77-79` (`Optional[...] = None`), `asset.py:114-116` (`AssetPartialId`).
- **Pre-existing oddity to preserve, not "fix":** `user.py:20,22` declare `analytics_optout: bool = None` and `auth_token: str = None` (non-Optional type, `None` default). These import fine in v2 (default present). Leave as-is unless instantiation surfaces it in Phase 2 — out of this phase's import-clean scope.

### v1→v2 API name map (apply across all source edits)
**Source:** RESEARCH.md "State of the Art" (lines 360–368)
- `pydantic.main.ModelMetaclass` → `create_model` + `model_fields` (meta.py)
- `@validator` → `@field_validator` + `ValidationInfo` (asset.py)
- `pydantic.json.pydantic_encoder` → `model_dump(mode="json")` + `json.dump(default=...)` (io.py)
- `.dict()` → `.model_dump()` — **DEFERRED to Phase 2** (api/*), do not touch now.
