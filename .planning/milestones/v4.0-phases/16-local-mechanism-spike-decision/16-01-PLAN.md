<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Google web page → probe parser | Untrusted HTML crosses into parsing (regex + tolerant JSON); a malformed page must fail loud, never hang or emit partial item lists silently |
| Share link → committed evidence | Capability URLs are secrets-like: anyone holding one sees the album — they must never cross into committed files |
| Downloaded bytes → frame's hash convention | The `=d` file is untrusted input to the fidelity comparison; hash is computed over raw bytes with no re-encoding |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-16-01 | Information Disclosure | committed evidence files | high | mitigate | `redact_link()` on all output paths + Task 3's verify greps committed files for full-length AF1Qip tokens; `.gitignore` keeps `.probe-downloads/` and `*.link` untracked |
| T-16-02 | Tampering | AF_initDataCallback parsing | medium | mitigate | fail-loud on missing `ds:1` (test 2); tolerant parse logs its fallback use; item count printed for human cross-check against Google Photos UI |
| T-16-03 | Information Disclosure | probe stdout/logs | medium | mitigate | redaction applied at the single print site in `probes/common.py` so raw URLs never reach terminal scrollback in committed form |
| T-16-04 | Denial of Service | probe fetches | low | accept | single-album, low-frequency fetches; 30s timeout; no retry loop that could look like bulk scraping |
</threat_model>
