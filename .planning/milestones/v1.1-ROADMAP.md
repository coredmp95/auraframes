# Milestone v1.1: Client Transport Seam for Offline Testability

**Status:** ✅ SHIPPED 2026-07-05
**Phases:** 4-4
**Total Plans:** 3

## Overview

Deepened `Client` into a real transport seam so the whole `*Api`/`Aura` read-path stack
can be tested offline against canned payloads, lifting most of `test_read_path.py`'s
assertions off the live network. This was architecture-review candidate #1 identified
after v1.0 shipped, and is the first slice of a broader "lift tests off the live network"
effort (candidates #2 authenticated value, #4 injected config remain open for a future
phase).

## Phases

### Phase 4: Client transport seam for offline testability

**Goal**: Deepen `Client` into a real transport seam so the whole `*Api`/`Aura` read-path stack can be tested offline against canned payloads — lifting most of `test_read_path.py` off the live network.
**Requirements**: R4-SEAM-CLIENT, R4-SEAM-AURA, R4-FIXTURES, R4-FIXTURE-VALIDITY, R4-HARNESS, R4-OFFLINE-TESTS, R4-LIVE-UNCHANGED
**Depends on**: Phase 3
**Plans**: 3 plans

Plans:

- [x] 04-01: Additive transport/client DI seam on `Client.__init__`/`Aura.__init__` (wave 1)
- [x] 04-02: Sanitized model-valid fixtures + fixture-validity pytest (wave 1)
- [x] 04-03: Offline harness (`tests/offline.py`) + offline read-path test module (wave 2)

**Details:**

**Settled design (via `/grilling` — architecture review 2026-06-30):**

- `Client.__init__(self, history_len=30, transport=None)`: `transport=None` builds the real httpx client exactly as today; when supplied, pass it to `httpx.Client(transport=transport)`. All `Client` behaviour (header defaults, `raise_for_status`, `_redact` logging, cookie persistence, history) stays behind the interface.
- `Aura.__init__(self, client=None)`: `self._client = client or Client()`. Closes the existing `# TODO: Can probably use DI` at `aura.py:28`. Two seams: `Aura ← Client ← transport`.
- `base_url` stays hardcoded (endpoint config deferred to candidate #4). Both constructors stay zero-arg compatible — `main.py` and all callers untouched; pure additive params.
- Auth/login mechanism untouched (the `add_default_headers` mutation is candidate #2's concern). Return types untouched — raw-dict → typed envelope deferred to candidates #5/#6.

**Test plan delivered:**

- Reusable offline harness in `tests/offline.py`: an `httpx.MockTransport` router keyed `request.url.path → fixture`, exposed as `offline_aura(fixtures)` returning `Aura(client=Client(transport=MockTransport(router)))`.
- 5 sanitized fixtures under `tests/fixtures/*.json` (login, frames, assets_page1, assets_page2, error_envelope) — synthetic (not recorded from the live API), hand-authored to minimal shapes, driving the `get_all_assets` cursor loop with a 2-page asset pair.
- New offline tests (default `pytest` run, no creds): login header-set, `get_frames` hydration, `get_all_assets` pagination drain, error-envelope raise (business-rule `RuntimeError` and `httpx.HTTPStatusError`).
- The existing `@live` tests remain byte-identical and untouched as the drift oracle.

**Verification:** 7/7 must-haves passed. UAT: 8/8 tests passed, 0 issues.

## Milestone Summary

**Key Decisions:**

- `Client(transport=...)` / `Aura(client=...)` additive DI seam — zero-arg callers (`main.py`, existing tests) unaffected (D1)
- Fixture JSON authored entirely synthetic (no real recorded API response) — safer sanitization posture, no real secret ever exists to leak (D-Phase4-P2)
- `assets_page1`/`assets_page2` fixtures distinguished by `next_page_cursor` truthiness + distinct asset ids for the pagination router (D-Phase4-P2)
- `offline_aura()`'s overrides mechanism is a plain dict keyed by the fully-resolved path, checked before the router's default branches (D-Phase4-P3)
- Removed the DI TODO comment in `aura.py` outright rather than rephrasing it (D-Phase4-P1)

**Issues Resolved:**

- Closed the long-standing `# TODO: Can probably use DI` in `aura.py`
- Most of `test_read_path.py`'s assertions now run offline with zero network/credentials, while the `@live` suite remains the drift oracle

**Issues Deferred:**

- Code review flagged a pre-existing bug as a warning (not fixed here): `Aura._init_logger()` leaks loguru sinks/log files on repeated `Aura()` construction, amplified by the new per-test `offline_aura()` pattern
- Architecture-review candidates #2 (authenticated value) and #4 (injected config) remain open for a future phase to complete the "lift tests off the live network" slice

**Technical Debt Incurred:**

- None new; existing known debt (hardcoded AWS pool IDs/bucket, unguarded post-login state, silent `pass` on some API `error` fields, sync-only HTTP) carries forward unchanged

**Note on requirements tracking:** This milestone had no standalone `REQUIREMENTS.md` — Phase 4's requirements (R4-SEAM-CLIENT, R4-SEAM-AURA, R4-FIXTURES, R4-FIXTURE-VALIDITY, R4-HARNESS, R4-OFFLINE-TESTS, R4-LIVE-UNCHANGED) were tracked inline in ROADMAP.md and PROJECT.md, since `REQUIREMENTS.md` had already been removed at the v1.0 close before Phase 4 was scoped.
